# Business

Доменная модель и продуктовый контекст. Полезно перед изменениями фичи: понять «зачем оно так».

## Что это

**NashDom** — маркетплейс недвижимости для Казахстана. Позиционирование: тёплый, человечный сервис вместо холодных листингов. Аналоги — krisha.kz, etazhi.kz, но с упором на UX и визуал.

## Доменные сущности

### User (пользователь)
Один пользователь — одна роль. Меняется только админом.

| Роль | Что может |
|---|---|
| `client` | Искать, открывать карточки, добавлять в избранное, отправлять заявки. **Не может** размещать объявления. |
| `realtor` | Всё что client + создавать/редактировать/удалять свои объявления + видеть статистику по ним. **Не видит** чужие приватные данные. |
| `superadmin` | Всё + модерация всех объявлений + управление пользователями + Django admin. |

`is_verified: bool` — признак подтверждённости аккаунта (галочка). Влияет только на видимый бейдж — функциональных ограничений пока нет (флоу верификации в роадмапе).

### Property (объект недвижимости)
Одна запись = одно объявление, владелец = один user (`owner`). Ключевые поля:

- **Тип** (`property_type` → справочник `PropertyType`): Квартира / Дом / Коммерция / Участок / Комната
- **Сделка** (`service_type` → `ServiceType`): Продажа / Аренда / Посуточно / Коммерческая аренда
- **Цена** (`price`, decimal в тенге)
- **Локация:** `city`, `district`, `address`, `latitude`, `longitude` (опционально)
- **Параметры:** `area` (м²), `rooms`, `floor`, `total_floors`, `has_parking`, `has_balcony`, `has_elevator`
- **Статус** (`status`): `active` (опубликовано) / `sold` (продано) / `rented` (сдано) / `inactive` (в архиве)
- **Промо:** `is_featured` — выводится в подборки на главной
- **Метаданные:** `views_count`, `created_at`, `updated_at`

### Изображения
Каждое Property имеет:
- `main_image` (FileField прямо в модели) — обложка
- Связанные `PropertyImage` (FK → property) — галерея, поле `is_main`, `order`

При сабмите формы фото грузятся как `uploaded_images` multipart-file array. Backend создаёт `PropertyImage` для каждого.

### Favorite
M2M user × property через таблицу `Favorite`. Toggle через `POST /api/properties/<id>/favorite/`. На карточке поле `is_favorited` рассчитывается в сериализаторе с context.request.user.

### Заявки (`ContactRequest`)
Заявка может быть:
- General — общий вопрос (форма «Свяжитесь с нами»)
- Property inquiry — по конкретному объявлению (`property` FK)
- Viewing — запрос на просмотр
- Callback — «перезвоните»

Статус: `new` / `in_progress` / `completed` / `cancelled`. Управляется админом.

### Newsletter
Простая модель `email + is_active`. Отписка через GET-ссылку с email в URL.

## Продуктовые правила

### Видимость объявлений
- Любой посетитель (без авторизации) видит **все объявления со статусом `active`**.
- `sold`/`rented`/`inactive` — не показываются в каталоге, но открываются по прямой ссылке (для истории).
- `is_featured` влияет на:
  1. Попадание в endpoint `/api/properties/featured/` (главная страница)
  2. Возможность фильтровать «Только рекомендуемые» в каталоге

### Кто что видит
| Сущность | Гость | Client | Realtor | Superadmin |
|---|---|---|---|---|
| Каталог | ✅ | ✅ | ✅ | ✅ |
| Карточка объекта (active) | ✅ | ✅ | ✅ | ✅ |
| Контакты владельца | ✅ | ✅ | ✅ | ✅ |
| Добавить в избранное | ❌ (редирект на login) | ✅ | ✅ | ✅ |
| Свой профиль | — | ✅ | (через дашборд) | (через дашборд) |
| Кабинет (`/dashboard`) | ❌ | ❌ | ✅ | ✅ |
| Создать объявление | ❌ | ❌ | ✅ | ✅ |
| Редактировать чужое | ❌ | ❌ | ❌ | ✅ |
| Админ-панель | ❌ | ❌ | ❌ | ✅ |

### Право редактирования
Объявление может редактировать **только владелец** (`property.owner == request.user`) или **superadmin**. Реализовано через `IsOwnerOrAdmin` permission.

### Counter просмотров
`views_count` увеличивается на 1 при каждом GET `/api/properties/<id>/`. Сейчас без дедупликации — если пользователь обновил страницу 5 раз, +5 просмотров. Это сознательно (для простоты). При росте трафика — добавить дедуп через session/cookie.

### Ипотека и новостройки — только информация
Сознательно **нет** отдельных разделов «Ипотека» и «Новостройки». Это чисто **контентные блоки** внутри карточки объекта (приближённый расчёт ипотеки, ссылки на ЖК). Исключение — если бизнес явно пойдёт в кросс-продажи финуслуг.

## Воронка пользователя (типовая)

### Гость → клиент
1. Заходит на главную → видит подборки + поиск
2. Использует SearchBar → попадает в `/properties` с фильтрами в URL
3. Кликает карточку → открывается `/properties/<id>` → смотрит фото, описание, карту
4. Хочет сохранить → жмёт сердечко → редирект на `/auth/login`
5. Регистрируется как `client` → возвращается → favorite добавлен
6. Кнопка «Позвонить» → tel:link

### Клиент → реальная сделка
- Сейчас платформа не закрывает сделку. Только **сводит** клиента и продавца.
- Дальше — звонок, личная встреча, договор вне платформы.
- Заявка через форму → попадает в `/admin/requests/` → админ обрабатывает.

### Риелтор → размещение
1. Регистрируется как `realtor` (форма register, выбирает таб) → доп.поля (компания, опыт, лицензия)
2. Аккаунт сразу активен (модерация = TODO)
3. `/dashboard` → метрики 0
4. «Подать объявление» → форма из 6 секций (включая location-picker на карте)
5. Объявление сразу публикуется (модерация TODO)
6. В кабинете видит свои объявления, может редактировать/архивировать

### Админ
- `/admin` (NashDom UI) — сводка + быстрые ссылки
- `/admin/properties` — модерация объявлений (поиск, фильтр, удаление)
- `/admin/users` — список пользователей
- `/admin/` (Django) — fallback для всего, что не покрыто UI

## География

- Основной рынок — **Казахстан** (5 крупных городов в дефолтном списке: Алматы, Астана, Шымкент, Караганда, Атырау)
- Геокодинг ограничен `countrycodes=kz`
- Цены в тенге (₸), форматирование `Intl.NumberFormat('ru-KZ')`
- Дефолтный город в city-picker — **Алматы** (но пользователь может сменить, выбор хранится в cookie)
- Локализация только на русский. Казахский — задел в дизайне (nav, city-picker), но i18n не настроен.

- Никаких комиссий, рекламы, подписок

## Не наша зона ответственности

- **Эскроу / транзакции** — мы не хранмм деньги
- **Документы (договор купли-продажи)** — пользователи договариваются вне платформы
- **Юридическая проверка** — на собственный риск пользователей
- **Транспорт / перевозка** — нет
- **Ремонт / клининг** — нет
- **Ипотека через нас** — нет (только информационно)
